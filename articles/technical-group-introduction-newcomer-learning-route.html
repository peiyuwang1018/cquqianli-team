刚进入机械组时，一个非常常见的问题是：

我到底应该学什么？

Fusion、SolidWorks、材料力学、机械原理、机械设计、加工、公差、轴承、齿轮、螺丝、仿真、3D 打印、电气基础、走线…… 如果把所有和机械有关的知识平铺出来，这张清单几乎没有尽头。 于是新人很容易陷入两个极端。 一种是觉得自己什么都不会，于是一直在“准备学习”，收藏了很多资料、看了很多视频，却迟迟不敢真正开始做东西。 另一种是很快进入项目，画了很多图、拆装了很多机器人，但能力长期停留在工具操作层面：知道某个按钮在哪里，却不知道一个结构为什么应该这样设计。

我越来越觉得，新人真正需要解决的问题并不是：

“我要先学完哪些知识？”

而是：

怎样建立一个能够持续运转的“学习—实践—反馈—再学习”循环？

机械设计能力不是把若干课程依次学完以后突然获得的。它更像一张不断扩大的地图：一开始你只认识几个局部，后来随着看过的结构、做过的项目和踩过的坑越来越多，原本彼此孤立的知识点开始产生连接。

01机械并没有想象中那么高的“天赋门槛”

新人有时候会把机械设计想象成一种很神秘的空间能力：

一个厉害的机械设计者，应该能够闭上眼睛就在脑子里把整台机器人旋转一遍，提前想清楚所有零件的位置，然后打开 Fusion，把脑子里的最终答案誊写出来。

空间想象力当然有帮助。经验丰富以后，我们也确实会越来越容易在脑子里预判结构关系。 但绝大多数机械设计，并不要求你拥有非常夸张的“颅内 CAD”能力。 因为我们本来就有 CAD。

脑中的模糊设想 → 画进 CAD → 获得可视化反馈 → 继续思考和调整

很多时候，你完全可以把建模软件理解成自己的外部空间思维工具。 脑子里先有一个大概：

电机可能放这里，轴从这里经过，另一侧还要给其他模块留空间。

先把它放进去。 真正出现在三维空间以后，你可能立刻发现：

  • 原来这里比想象中拥挤；
  • 电机其实还可以再向后移动；
  • 这个轴承位置让主体结构非常别扭；
  • 线束根本没有路径；
  • 两个模块的比例和空间关系完全不合理。

于是继续修改。 所以真实的设计过程很多时候并不是：

而更接近：

你不需要等到脑子里什么都想清楚以后，才有资格开始画。

CAD 本来就是帮助我们思考的工具。

02先看到，再聚焦：不要一开始就钻进细节

这一点和画画、雕塑、摄影其实有一些相似。 很多时候，我们不会一开始就把注意力全部扎进一个极小的细节。 画人物时，通常不会先把左眼睫毛画到极致，再开始考虑整个人应该站在哪里； 拍照时，也往往先决定构图、主体、背景关系，再去调整局部； 雕塑也需要先建立整体比例，再逐渐处理表面和细节。 机械设计也是一样。 如果一个项目的：

  • 整体包络；
  • 模块位置；
  • 运动范围；
  • 工作空间；
  • 重心；
  • 多模块接口；

非常重要，那么一开始就应该保留能够代表全局关系的草图、骨架或者 master geometry。 可以理解成：

先看到整体 → 再确定主要关系 → 再建立功能结构 → 最后进入局部细节

先看森林，再看树。 但这也不是一条僵硬的规定。 有些小模块本身并不复杂，功能链条非常明确。这时完全可以从一个核心标准件或者关键功能件开始，然后按照逻辑链条逐步向外生长：

所以真正重要的并不是：

“所有设计必须先画整体。”

而是：

你要知道自己现在处在哪个层级，并且不要因为一个局部细节失去对整体关系的判断。

03像下围棋一样：落这一步的时候，往后算几步

CAD 可以帮助我们思考，并不意味着机械设计应该：

想到哪，画到哪。

我更喜欢把设计过程类比成下围棋。 高手落下一颗棋子的时候，不是单纯因为：

“这个位置现在看起来不错。”

而是因为这一手会影响后面的若干步。 机械设计也是一样。 当你决定：

“这个轴承放在这里。”

最好已经顺便想到：

  • 内圈之后怎么定位？
  • 外圈怎么定位？
  • 另一侧有没有支撑？
  • 轴怎么装进去？
  • 端盖还能不能装？
  • 工具伸不伸得进去？
  • 轴承孔由谁加工？
  • 线束是否还能够穿过去？
  • 如果以后轴承改规格，哪些东西会跟着变化？

也就是说：

画当前一步 + 提前预见后面的几步

这可能比所谓“超强空间想象力”重要得多。 一个成熟设计者真正厉害的地方，往往不是能够在脑子里渲染出多复杂的模型，而是：

知道当前这个决定接下来可能产生什么后果。

这也是以后《设计者视角》会反复讨论的“设计因果”。

从“看到”到“预见”

04画图熟能生巧：先让手快起来

另一个非常常见的误区是：

机械设计 = 会用 CAD 软件。

当然不是。 两个都非常熟练使用 Fusion 的人，面对同一个任务，依然可能做出水平差异极大的方案。 真正拉开设计水平的能力，大致可以分成三层：

工具层 → 范式层 → 思维层

工具层

你能不能迅速把想法表达出来？ 例如：

  • 草图；
  • 参数；
  • 拉伸和切除；
  • 基准；
  • 装配关系；
  • Timeline；
  • 工程图；
  • 基本的模型组织。

范式层

你脑子里有没有足够多成熟的机械“公式”？ 例如：

  • 一根轴通常怎么支撑；
  • 电机怎么安装；
  • 同步带怎么张紧；
  • 薄壁结构怎么连接；
  • 一个转轴如何走线；
  • 常见模块有哪些成熟拓扑。

思维层

面对新的问题，你能不能：

  • 抓住主要矛盾；
  • 判断约束；
  • 做合理 trade-off；
  • 看出模块耦合；
  • 预见当前决策后果；
  • 灵活组合已有范式；
  • 在成熟范式失效时进入自主探索。

所以：

CAD 熟练度 ≠ 机械设计水平

但这里千万不要走向另一个极端：

“既然工具不能代表设计水平，那画图软件随便会一点就够了。”

恰恰相反。 越基础的东西，越应该尽早练熟。

05先让手追上脑子，再让脑子跑到手前面

新人刚开始画图时，经常是：

这时候真正限制效率的，往往还不是设计能力，而是工具本身。 所以前期一个很重要的目标就是：

先让手快起来。

画得多，改得多，处理过足够多真实装配体以后，很多操作会逐渐变成接近肌肉记忆的东西。 你不再需要为了：

“这个命令在哪里？”

分配大量注意力。 于是原本被工具占据的认知资源，才会逐渐释放出来，用来思考真正的设计问题。 我更愿意把这个成长过程概括成：

先让手快起来 → 让经验堆起来 → 让脑子追上手 → 最后让脑子比手更快

第一阶段：手追脑子

你已经大概知道自己想画什么，但软件操作还跟不上。 一个简单想法落实到 CAD 里要花很久。

第二阶段：手开始变快

随着熟能生巧，工具本身不再成为主要障碍。 你终于可以做到：

想到一个结构，就快速画出来看看。

CAD 开始真正成为思维工具。

第三阶段：经验进入脑子

画过足够多结构、经历过足够多项目以后，你开始在下手以前主动预判：

  • 这里后面可能装不上；
  • 这个轴承这样布置，另一边一定还需要限位；
  • 这个主体继续这么长，线束大概率没有空间；
  • 这个地方以后很可能反复改，暂时不要把依赖写死。

这时：

脑子开始追上手。

第四阶段：脑子比手更快

再往后，设计效率的提高已经不主要来自：

“一分钟能拉伸多少次。”

而来自：

少画了多少必然要删掉的东西。

你在画当前特征以前，脑子已经顺着因果链向后走了几步：

所以设计效率最终会发生一次变化：

工具不是设计能力的上限。 但基础工具如果长期不熟练，上层思考也很难高效落地。

06看开源，就像写文章以前读经典

这里还有一个我很喜欢的类比。 学习机械设计和学习写文章，其实有一点相似。 如果一个人几乎没有读过任何好的文学作品，却要求他：

“现在请完全原创地写出一篇优秀文章。”

当然不是绝对不可能。 但除非是极少数天才，大多数人都会非常困难。 因为：

肚子里没有墨水。

机械设计也是一样。 如果一个新人：

  • 没看过成熟机器人；
  • 没研究过成熟轴系；
  • 不知道常见传动怎么布置；
  • 不知道别人如何处理接口；
  • 没见过优秀的结构细节；

第一次接到任务，就要求：

“不要参考别人，自己原创一个。”

这其实不是很合理的学习方式。 看优秀开源，就像阅读经典作品。 目的不是最后让所有人写出一样的句子。 而是在阅读过程中逐渐形成自己的：

  • 词汇；
  • 句式；
  • 结构；
  • 表达方式；
  • 审美和判断。

对应到机械里，就是逐渐积累：

标准件 + 结构范式 + 实现案例 + 失败经验

最后这些东西才会变成你设计时能够自由调用的“机械语言”。 所以：

“这个设计参考了某个成熟开源。”

不是一件需要羞于承认的事情。 真正需要担心的是：

只抄到了作者最后写出来的句子，却没理解他为什么这样写。

07机械领域也有自己的“公式化做题”

成熟范式的作用，其实和公式非常像。 例如看到：

“我要支撑一根旋转轴。”

如果脑子里完全没有任何范式，你面对的是一个巨大的搜索空间。 但看过很多成熟轴系以后，你可能自然想到：

  • 深沟球轴承；
  • 角接触轴承；
  • 交叉滚子轴承；
  • 两支点布置；
  • 定位端 / 游动端；
  • 内外圈如何约束。

于是问题从：

“完全不知道怎么办。”

变成：

识别问题 → 寻找已有范式 → 判断适用条件 → 修改参数和接口 → 验证

这就是机械领域自己的：

公式化做题。

新人阶段能够正确地“套公式”，本身就是一种重要能力。 真正需要反对的是：

而不是：

具体怎么从“看几何”走到“理解设计”，会在：

《设计者视角 03｜怎么看开源？》

中展开。

08先在有路的地方学会走，再考虑自己进沙漠

关于设计范式，我以前还喜欢用另外一个比喻。 有些工程问题像：

一条已经修好的道路。

甚至到了分岔口，还有路牌告诉你有哪些选择。 这种问题已经有比较成熟的“确定范式”。 例如很多：

  • 标准轴系；
  • 螺纹连接；
  • 常见传动；
  • 工业标准件应用；

并不值得新人每一次都重新从零探索。 另一类问题则更像：

站在一片沙漠里，地图上没有路，手里只有指南针。

例如：

  • 新赛季第一次出现的新地形；
  • 高度耦合的新型机构；
  • 没有成熟参考的功能拓扑。

这时候自主探索当然是必要的。 但对于新人而言：

先学会在有路标的地方走 → 再逐渐学习如何在没有路的地方找方向

通常更加合理。 随着经验越来越多，你也会发现一个很有意思的变化：

以前看起来像“沙漠”的问题，后来经常会被拆成几个自己已经见过的子问题。

这就是范式积累的价值。

09不要好高骛远：创新不是日常工程的默认状态

新人有时候会把：

“我参考了别人。”

理解成：

“我不够厉害。”

于是产生一种很危险的执念：

我一定要从零做一个从来没人做过的东西。

我觉得完全没有必要。 真正从底层创造一种新的机械范式，本来就是非常困难、非常稀有，也非常珍贵的事情。 绝大多数日常工程创新更接近：

成熟范式 A + 成熟范式 B + 当前问题的特殊约束 → 新的具体方案

例如：

  • 把已有传动换一种位置；
  • 把两个功能合理集成；
  • 把成熟模块适配进新的空间；
  • 重新组织几个标准结构；
  • 消除旧方案真正的系统瓶颈。

这些都完全可以是有价值的创新。 所以：

创新不是目的，解决问题才是目的

如果成熟方案已经很好地解决问题：

用它。

如果它在当前场景不完全适合：

修改和化用。

如果现有范式真的成为性能瓶颈：

再投入更高风险的探索。

10先建立基本盘，再谈更高层次的优化

这和创新问题其实是同一件事。 新人第一次独立做模块时，特别容易同时被大量问题绑架：

  • 会不会不够轻？
  • 会不会不够漂亮？
  • 集成度是不是还不够高？
  • 第一版是不是应该直接做到最终形态？
  • 有没有更加“高级”的方案？

结果一周以后：

CAD 还停在草图。

工程研发更现实的方式通常是：

V0：验证核心原理 → V1：实现完整功能 → V2：进入真实系统 → V3+：持续优化

先建立：

稳定可用的基本盘。

然后让现实告诉你下一步最值得优化什么。 否则很容易为了一个还没有真正发生的问题，提前投入大量时间。

MVP 不等于随便做

“先做出来”也绝不意味着：

  • 图可以乱画；
  • 明知道会干涉也无所谓；
  • 不看任何成熟经验；
  • 完全不考虑装配；
  • 不做基本强度判断；
  • 低级错误随便犯。

MVP 真正想解决的是：

不要让次要优化阻止核心功能尽早获得真实反馈。

技术洁癖和第一版完美主义不是一回事。

学校课程往往看起来是：

但工程学习更常见的是：

所以：

工程知识不是一次学会，而是在不断重访中逐渐加深

有些东西第一次读会觉得：

“这不是废话吗？”

半年以后再看，突然发现每一句都对应一个自己踩过的坑。 不是知识变了。 是你脑子里终于有经验可以承载它了。

12不要把输入很多，当成学得很好

看视频、读文章、看开源当然都很重要。 但离开考试以后，我们必须自己回答：

我怎么知道自己真的学会了？

最直接的方法就是：

输出。

例如：

  • 给别人解释一个结构；
  • 做一次小分享；
  • 写一份技术笔记；
  • 重新画一遍；
  • 修改一个关键参数；
  • 自己做一个相似模块；
  • 回答别人为什么这么设计。

如果只能说：

“我看懂了。”

但别人继续问：

“那为什么电机要放这里？”

就答不上来，那其实是一个非常有价值的反馈。 因此：

输入 → 输出 → 暴露理解漏洞 → 重新输入

输出不是学习结束后的展示。 输出本身就是学习。

13犯错正常，但要尽量犯“有价值的错”

机械学习一定伴随错误。 很多经验甚至只有真正踩过以后才会记住。 但不同错误的价值完全不同。

有价值的错误

你认真分析了一个以前没有处理过的问题，做出合理判断，但现实证明假设错了。 这种错误很宝贵。

低价值的重复错误

某个问题：

  • 队内文档写过；
  • 成熟开源说明过；
  • 老队员提醒过；
  • 以前机器人踩过；

但因为完全没有查资料，又完整交了一次学费。

本来可以被流程拦截的错误

例如：

  • 忘记检查干涉；
  • 漏特征；
  • 螺丝规格明显错误；
  • 图纸版本没更新；
  • 装配顺序完全没想。

这些应该逐渐通过：

  • checklist；
  • 审图；
  • mentor；
  • 组会；
  • 规范；

降低概率。 所以：

不害怕犯错 ≠ 不需要谨慎

理想状态是：

把试错成本留给真正值得探索的问题。

14学会提问，本身就是工程能力

一个好的问题，本身通常已经包含一部分分析。 比如：

“这个为什么不行？”

提供的信息非常少。 而：

“这个轴承空载转动正常，但工作五分钟以后阻力明显增加。目前内圈和外圈都偏紧，我怀疑温升后游隙进一步减小。有没有可能是配合导致的？”

这个问题已经包含：

  • 现象；
  • 时间条件；
  • 当前结构；
  • 自己的猜想。

别人也更容易真正帮助你。

推荐的提问结构

1. 我在做什么？

说明模块和目标。

2. 我遇到了什么？

Expected / Actual。

3. 我尝试了什么？

避免别人让你重新走已经走过的路。

4. 我现在怎么理解？

即使猜错，也把自己的机制假设说出来。

5. 给足信息

例如：

  • CAD 截图；
  • 实物照片；
  • 视频；
  • 尺寸；
  • 工况；
  • 测试记录。

15尽量让问题和经验留在公共空间

如果一个问题不涉及保密或者私人内容，我更推荐：

在培训群、项目群或者论坛公开提问。

因为：

而：

对于培训者也是一样。 同一个问题被十个人私聊问十次，是非常低效的知识传播方式。 一个好的技术团队应该尽量让：

问题 + 回答 + 讨论过程

留下来。

16新人手里的资源，其实比想象中多

刚进入机械组时，很容易觉得：

“我什么都没有。”

实际上通常已经有很多资源可以利用。

实物资源

  • 历年机器人；
  • 废旧模块；
  • 标准件；
  • 加工设备；
  • 3D 打印；
  • 测量和装配工具。

尤其不要低估旧机器人。 CAD 看不到：

  • 磨损；
  • 松动；
  • 线束；
  • 油污；
  • 临时维修；
  • 比赛碰撞留下的变形。

而这些都是工程的一部分。

信息资源

  • 队内知识库；
  • 培训文档；
  • RoboMaster 开源；
  • 历年研发记录；
  • 测试结果；
  • CAD；
  • 工程图。

人力资源

  • mentor；
  • 老队员；
  • 项目负责人；
  • 电控 / 视觉 / 算法成员。

真正会利用资源，并不是遇到问题立刻问别人答案。 更合理的过程是：

先自己理解 → 查已有资料 → 形成问题 → 再寻求反馈

具体有哪些课程、频道、网站和工具值得推荐，会单独放在：

机械组导言（三）｜推荐资源与工具索引

这篇不再展开具体清单。

17真正重要的是建立一个高频反馈系统

如果只能给新人一个学习建议，我可能不会只说：

“多看书。”

也不会只说：

“多画图。”

而会说：

尽快建立一个高频、真实的反馈循环。

例如：

如果一个设计连续一个月都没有：

  • 被制造；
  • 被测试；
  • 被别人审图；
  • 被真实使用；

那它获得反馈的速度通常很慢。 可以粗略理解为：

学习效率 ≈ 反馈频率 × 反馈质量

18高频不等于爆肝：可持续比短期冲刺更重要

机械能力需要长期积累。 如果刚开始：

两周每天做到凌晨，

然后第三周：

完全不想来了，

通常不如长期保持：

  • 每周看一点；
  • 每周画一点；
  • 每周做一点；
  • 持续和 mentor 交流；
  • 阶段性完成小目标。

所以长期成长更像：

长期成长 ≈ 有效投入 × 反馈质量 × 持续时间

三个里面任何一个长期接近零，结果都不会特别理想。

19我更推荐的四阶段成长路线

前面的内容最后可以落到一个比较粗略的成长地图。 这不是考试等级，也不是晋升条款，只是帮助新人判断自己当前的位置。

STEP 1｜看懂、修改、复刻

重点：

  • 学工具；
  • 认识结构；
  • 看成熟开源；
  • 积累范式；
  • 能修改已有设计；
  • 能移植简单结构。

核心目标：

肚子里开始有“墨水”

STEP 2｜走完整项目闭环

经历：

设计 → 加工 → 装配 → 测试 → 迭代

开始真正理解：

CAD 里的机器和现实里的机器有什么差别。

STEP 3｜独立设计完整模块

任务从：

“照着这个改。”

变成：

“这里需要这个功能，你给方案。”

这时候开始真正使用：

需求 + 范式 + 约束 → 具体设计

STEP 4｜统筹多个耦合模块

进一步考虑：

  • 模块之间如何影响；
  • 接口如何定义；
  • 空间如何协调；
  • 机械、电气、视觉如何共同工作；
  • 哪些局部优化会伤害系统。

开始从“模块设计者”逐渐走向：

系统设计者。

【成长路线】

现实成长并不会严格按照四个台阶一次通过。 更多时候是在几个阶段之间反复横跳、螺旋上升。

20最后：你不需要一次学会整个机械工程

再回到最开始的问题：

“我到底应该学什么？”

我的答案是：

先学当前问题真正需要的东西。

然后在一个又一个项目里，把自己的知识地图慢慢扩出去。 你不需要：

学完整本材料力学，才开始画机器人；

也不需要：

学完整套有限元理论，才允许第一次做结构。

更现实的过程是：

遇到问题 → 知道自己缺什么 → 找到资源 → 应用 → 获得反馈 → 留下经验

随着这个循环不断重复，你会发现： 以前完全陌生的问题开始变成熟悉问题； 以前只能照着别人画的结构，开始能够自己修改； 以前需要别人提醒：

“这里要注意这个。”

后来会在画第一根线以前自己想到。 而工具能力本身也会经历：

手追脑 → 手变快 → 经验积累 → 脑追上手 → 脑子最终跑到手前面

我觉得这才是机械新人真正成长起来的标志。 不是终于背完了某一本书。 而是面对一个新的问题时，你越来越知道：

下一步应该往哪里走，以及为什么。

21如果只留下几条建议

  • 不要等自己“准备充分”才开始做。
  • 空间想象力不够并不可怕，CAD 本来就是帮助你可视化思考的工具。
  • 先看到整体，再逐渐聚焦；即使从局部开始，也要提前往后想几步。
  • 工具层不是设计水平本身，但工具一定要练熟。
  • 先让手快起来，让经验堆起来，最后让脑子比手更快。
  • 多读优秀开源，就像写文章以前多读经典；肚子里没有墨水，很难凭空写出好东西。
  • 新人阶段正确“套公式”没有问题，关键是理解适用条件。
  • 不要为了创新而创新；成熟范式的移植、化用和组合，本来就是工程常态。
  • 先建立稳定可用的基本盘，再通过真实反馈持续优化。
  • 不害怕犯错，但不要反复支付已经有人交过的学费。
  • 多输出，多公开讨论，让理解漏洞尽早暴露。
  • 建立高频反馈循环，同时保持可持续的长期节奏。

真正希望新人最终形成的，不是一张越来越长的知识点清单，而是一套能够长期自我运转的方法：

观察与学习 → 实践 → 反馈 → 理解 → 再次实践
